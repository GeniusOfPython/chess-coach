# ADR-0001: Границы модулей

- Статус: Принято
- Дата: 2026-07-21

## Контекст

Приложение объединяет шахматные правила, расчёт движка, обучение, React-интерфейс, хранение данных и серверный ИИ-контур. Свободные импорты между этими областями создают циклы и делают локальное изменение опасным.

## Решение

- `analysis`, `game`, `features` содержат предметные правила и не импортируют React, `components`, `hooks` или `app`.
- `engine` зависит только от нейтральных типов и внешнего протокола движка.
- `ai` использует проверенные шахматные факты, продуктовые права и платформенные адаптеры, но не UI.
- `platform` содержит хранение, нативные мосты, PWA и адаптер аналитики.
- `components` отображают состояние; `hooks` связывают предметные модули с React; `app` выполняет композицию верхнего уровня.
- Сервер использует из клиентского дерева только общие контракты `ai`, `analysis` и `types`.
- Циклические импорты запрещены.

Тип рабочей области перенесён из React-компонента в `game/workspaceNavigation.ts`, чтобы предметный модуль не зависел от UI.

## Контроль

`npm run check:architecture` анализирует статические импорты TypeScript/JavaScript и завершает проверку ошибкой при запрещённой зависимости или цикле. Команда входит в `npm run check`.

## Последствия

Новый общий тип размещается в наиболее низком подходящем слое, а не в компоненте-потребителе. Изменение границ требует отдельного ADR и обновления исполняемой проверки.
