# ADR 0007: performance-бюджеты и Core Web Vitals

- Статус: Принято
- Дата: 2026-07-22

## Контекст

Рост интерфейса, локального движка и PWA-кеша может незаметно увеличить время
первого запуска, расход памяти и объём обновлений. Проверка только факта успешной
сборки не обнаруживает такую регрессию.

## Решение

Размеры измеряются по фактическому `dist` после production-сборки. Бюджеты
начальных JS/CSS, всего артефакта и WebAssembly движка хранятся в одном
версионируемом файле `performance-budget.json`.

LCP, CLS и INP измеряются Performance Timeline API в настоящем Chromium на той
же production-сборке, которая проходит остальные E2E. Порогами служат границы
категории good: 2500 мс, 0,1 и 200 мс соответственно.

Обе проверки обязательны для релизного quality gate. Изменение бюджета требует
осознанного изменения конфигурации и проверки причины роста, а не автоматического
повышения лимита.

## Последствия

- регрессия размера блокирует локальный и CI gate;
- регрессия пользовательской производительности блокирует полный CI gate;
- отчёты сохраняют фактические значения для сравнения между сборками;
- Stockfish учитывается отдельно и не маскирует рост стартового интерфейса.
