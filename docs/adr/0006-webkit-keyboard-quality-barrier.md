# ADR 0006: WebKit и клавиатура как релизные барьеры

## Статус

Принято.

## Контекст

Chromium-проверки не обнаруживают все различия Safari, а общий WCAG-аудит не
доказывает, что интерфейс можно последовательно использовать без мыши.

## Решение

- Критический учебный цикл и клавиатурный сценарий запускаются в Playwright
  WebKit с профилем Desktop Safari.
- Chromium отдельно проверяет клавиатурный маршрут и порядок фокуса.
- Вкладки рабочих областей реализуют шаблон ARIA Tabs: одна Tab-остановка,
  стрелки для соседних вкладок, `Home` и `End` для краёв.
- В начале страницы есть ссылка пропуска к рабочей области.
- Оба барьера обязательны в полном quality gate.

## Последствия

CI устанавливает Chromium и WebKit. Несовместимость Safari или нарушение
клавиатурного маршрута блокирует релиз и сохраняет Playwright-диагностику.
