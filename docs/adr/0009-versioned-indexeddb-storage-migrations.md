# ADR 0009: Версионированное хранилище IndexedDB

Статус: принято, 22 июля 2026 года.

## Контекст

Синхронный `localStorage` подходит для небольших настроек, но ограничивает рост
архива партий, учебного журнала и будущей синхронизации. Прямое переключение на
асинхронную базу могло потерять текущую партию или сломать запуск в приватном
режиме браузера.

## Решение

- Основное постоянное хранилище — IndexedDB `chess-coach`.
- Схема изменяется только последовательными миграциями с номером версии.
- Версия 1 создаёт stores `app-data` и `metadata`.
- Первый импорт записей `chess-coach.*` выполняется одной транзакцией.
- Существующие значения IndexedDB имеют приоритет и не перезаписываются
  устаревшим `localStorage`.
- После загрузки приложение читает синхронный снимок из памяти, а изменения
  последовательно записывает в IndexedDB.
- На переходный период `localStorage` остаётся совместимым зеркалом для отката
  на предыдущую версию приложения.
- При недоступной IndexedDB запуск автоматически остаётся на `localStorage`.
- Ключи других приложений никогда не импортируются и не очищаются.

## Гарантии

Импорт имеет маркер завершения и не повторяется. Обновление схемы блокируется,
если другая вкладка удерживает несовместимую версию базы; приложение в этом
случае использует fallback. Резервная копия считается восстановленной только
после завершения очереди записи.

## Проверки

Unit-тесты контролируют порядок версий, выбор основного снимка, двойную запись и
fallback. E2E переносит реальную текущую партию, перезагружает приложение после
очистки зеркала и отдельно запускает его с отключённой IndexedDB.
