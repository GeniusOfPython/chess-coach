# AI Coach backend contract

Клиент вызывает только `POST /api/coach`. Ключ провайдера никогда не
передаётся в браузер или Capacitor и хранится на сервере в `OPENAI_API_KEY`.

## Обязанности endpoint

1. Авторизовать пользователя и применить лимит Free/Premium.
2. Проверить `AiCoachRequest` версии 1 и ограничить размер тела запроса.
3. Вызвать OpenAI Responses API с моделью из серверной переменной
   `OPENAI_MODEL`.
4. Использовать Structured Outputs со строгой JSON Schema, совпадающей с
   `AiCoachResponse` из `src/ai/coachContract.ts`.
5. Вернуть JSON без markdown. Ошибки лимита возвращать как HTTP 429.
6. Не журналировать полный FEN вместе с идентификатором пользователя без
   отдельного согласия; хранить только агрегированные метрики задержки и ошибок.

## Принципы промпта

- Stockfish остаётся источником шахматной оценки и вариантов.
- Модель объясняет уже рассчитанные данные простым русским языком и не должна
  придумывать другой «лучший ход».
- Ответ содержит один заголовок, краткое объяснение, 1–3 ориентира,
  необязательное предупреждение и один вопрос для обучения.
- На сервере должны быть таймаут, rate limit, бюджет использования и отдельные
  OpenAI projects для staging/production.

Клиентский контракт намеренно не содержит имени, email, истории аккаунта,
рекламного идентификатора, резервной копии или полного PGN.

## Реализованный endpoint

- `api/coach.ts` — serverless-адаптер `POST /api/coach`.
- `server/aiCoachServer.ts` — независимое от хостинга ядро, проверка входа,
  OpenAI-провайдер и заменяемый limiter.
- Максимальный запрос — 16 КБ, ответы не кешируются.
- Запрос к OpenAI использует `store: false`, тайм-аут 12 секунд и строгую
  JSON Schema. Текст upstream-ошибок не возвращается клиенту.

Скопируйте `.env.example` в локальную серверную конфигурацию и задайте
`OPENAI_API_KEY` и `OPENAI_MODEL`. Переменные без префикса `VITE_` не попадут
в клиентскую сборку.

После успешного развёртывания `/api/coach` установите клиентский флаг
`VITE_AI_COACH_ENABLED=true` и пересоберите приложение. Пока флаг выключен,
интерфейс показывает подготовленное состояние без неработающей кнопки.

## Проверка в браузерной разработке

1. Скопируйте `.env.example` в `.env.local`.
2. Заполните `OPENAI_API_KEY`, `OPENAI_MODEL` и установите оба переключателя:
   `AI_COACH_SERVER_ENABLED=true` и `VITE_AI_COACH_ENABLED=true`.
3. Перезапустите `npm run dev`, чтобы Vite перечитал переменные.
4. Запустите анализ позиции и нажмите «Спросить ИИ-тренера».

Vite обслуживает `/api/coach` через серверный middleware. Ключ не включается в
клиентский JavaScript: в браузер попадает только публичный флаг доступности.
Без заполненного ключа endpoint отвечает `503`, а партия и локальный Stockfish
продолжают работать независимо.

## Защита бюджета

- Серверный kill switch `AI_COACH_SERVER_ENABLED` по умолчанию выключен.
- Каждый ответ ограничен 450 output-токенами.
- Free получает 3 совета в день, Premium — 300 в месяц.
- Общий предохранитель текущей конфигурации — 500 запросов в день на процесс.
- Responses API usage учитывается по фактическим input/output-токенам. Перед
  каждым внешним вызовом резервируется консервативная максимальная стоимость,
  поэтому параллельные запросы не могут незаметно пробить дневной предел.
- `AI_COACH_DAILY_BUDGET_USD` задаёт дневной предел в долларах. После его
  достижения новые внешние вызовы автоматически прекращаются до следующих
  суток UTC. По умолчанию предел равен $1 на процесс.
- Цены input/output-токенов задаются серверными переменными и должны
  обновляться при смене модели или изменении прайсинга.
- Одинаковые позиции кешируются на час; параллельные одинаковые запросы
  объединяются в один вызов провайдера.
- Burst limiter допускает не более 5 запросов в минуту на клиента.

In-memory квоты, денежный бюджет и кеш подходят для локальной разработки и
закрытого теста. Serverless-инстансы не разделяют память, поэтому перед
публичным релизом `createMemoryCoachBudget` и `createMemoryCoachCostController`
необходимо заменить реализациями с атомарными счётчиками в постоянном
хранилище. До появления авторизации production adapter считает всех клиентов
Free и не доверяет тарифу из браузера.

Текущий limiter хранится в памяти serverless-инстанса и нужен для безопасного
первого запуска. Перед коммерческим релизом его следует заменить реализацией
`ConsumeCoachQuota`, использующей авторизованный account id и постоянное
хранилище. Именно там будут различаться дневные квоты Free и Premium.
